# Order workflow

A client can skip payment or replay delivery in a server-owned synthetic order workflow with observable payment and shipment ledgers.

| Attribute | Value |
|---|---|
| Technology | REST API (Python handlers) |
| CWE | CWE-841 |
| OWASP | A06:2025, API6:2023 |
| Test scope | `state-machine-unit` |

[Vulnerable source](vulnerable/main.py) · [Corrected source](fixed/main.py)

## Correction

Enforce created-to-paid-to-delivered transitions before effects and reject replayed delivery; this local state-machine fixture does not model concurrent durability.

## Regression

```sh
python3 tools/lab.py test --case rest-api/order-workflow --strict
```

Run from the repository root. Exact inputs and expected outputs are in
[the catalog](../../../catalog/cases.json). Both variants are tested.

The runner also checks every declared file effect. `functional` vectors can specify a useful
operation that the vulnerable implementation did not support correctly; `robustness` vectors
exercise malformed inputs. `benign` vectors require identical expectations.
