# Tenant bulk update

A batch archive endpoint checks the first document's tenant and then updates every requested ID. A permitted first element can conceal unauthorized later elements. EDB-39473 motivates object-level mutation authorization; batch and tenant behavior are original extensions.

| Attribute | Value |
|---|---|
| Technology | REST API (Python handlers) |
| CWE | CWE-863 |
| OWASP | A01:2025, API1:2023 |
| Test scope | `executable` |

[Vulnerable source](vulnerable/main.py) · [Corrected source](fixed/main.py)

## Correction

Validate ownership of every requested object before any write, within one SQLite transaction, and retain the tenant predicate in each update. A rejected mixed batch must leave both owned and foreign rows unchanged. Client tenant fields cannot override session scope. The lab does not model a database-enforced row-level security policy.

python3 tools/lab.py test --case rest-api/tenant-bulk-update --strict
